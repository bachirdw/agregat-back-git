## Constats (par gravité)

1. **important / certain (testé)** — `packages/career-ops/inbox.js:8-9,31-35` + `tools.js` `checkPipelineInbox`. `inboxEntries(text, true)` refuse toute ligne « ressemblant » à une case à cocher mais hors du format strict : `- [X]` majuscule, puce `*`, entrée indentée (sous-liste), `- [x]` sans URL, URL sans schéma (`a.com/jobs/1`). Scénario : le propriétaire (ou Obsidian) a un `- [X] …` ou une sous-puce dans `data/pipeline.md` ; le moteur relit TOUT le fichier envoyé par `career_write` → « ligne N refusée » à chaque écriture, l'étape « boîte d'entrée traitée » est inatteignable. En lecture non stricte (Bilan) ces lignes sont ignorées silencieusement : compteurs faux. Correctif : accepter `[xX]`, `[-*+]`, indentation ; en strict, ne refuser que les lignes NOUVELLES ou modifiées (comparer au contenu précédent) ; une ligne `[x]` sans URL doit seulement être conservée.

2. **important / probable** — `domain-packs/career-ops/manifest.yaml` (`optionalFiles`) + `tools.js` `read()`. Seuls 4 fichiers sont déclarés optionnels. Le Skill dit « (if exists) » pour `article-digest.md`, `voice-dna.md`, et le flux lit `data/pipeline.md`, `data/pdf-index.tsv`, `data/scan-history.tsv`, `modes/_profile.md`, `config/profile.yml`. Scénario : espace neuf, l'agent lit `article-digest.md` (« ALWAYS » dans `_shared.md`) → ENOENT brut (`isError`) : le Bilan affiche `career_read : N réussis, 1 échoué`, l'agent peut croire à une panne et dériver. Correctif : étendre `optionalFiles` (ou, plus robuste, traiter ENOENT de tout chemin `userPath` en lecture comme `absent:true`).

3. **important / probable** — `tools.js:976,1087-1112` (timeout 60 s fixe, `maxBuffer: 200000`, jamais surchargé : `mcp-gateway/server.js:295` ne passe pas `scriptTimeoutMs`). `scan` sur de nombreux portails, `generate-pdf` (Chrome) ou `build-cv-html` dépassent facilement 60 s ou 200 ko de sortie. Dans ce cas `error.code` n'est pas un entier (`null` / `ERR_CHILD_PROCESS_STDIO_MAXBUFFER`) → message générique « échouée, annulée ou expirée », sortie partielle perdue, le script a pu écrire à moitié (PDF, TSV) sans que l'agent le sache. Correctif : timeout par script (scan/generate-pdf 300 s), renvoyer `stdout/stderr` partiels et un drapeau `timedOut`/`truncated` au lieu d'une erreur muette.

4. **important / certain (testé)** — `truth.js` `formatCareerBilan` (regex FR seulement). (a) « Evaluate this job offer … save the score » → `Non exécuté : aucune action … manquante` (aucun verbe anglais : evaluate/score/rate). (b) « Prépare mes candidatures » : pluriel non reconnu (`candidatur(?:e|er)` sans `\b` après `s`). (c) `requested` retire `ne … pas` jusqu'à la ponctuation : « Ne fais pas de brouillon mais envoie l'email » efface aussi « envoie l'email » → « envoi de courriel » jamais signalé. Impact : Bilan trop indulgent (faux négatif « rien de manquant »). Correctif : borner la négation à la proposition (couper aux conjonctions `mais|puis|et|but|and`), ajouter EN et pluriels ; mieux, s'appuyer d'abord sur `skillSteps`/`proves` plutôt que sur le texte du prompt.

5. **important / certain (chemin de code)** — `documents.js` `attachDocument` + `workspace.js` `upload`. Le PDF rendu est écrit sous `output/` AVANT `career.upload`, qui lance `pdftotext` ; si la conversion échoue (`pdftotext` absent du PATH du processus Relay — ici présent dans /opt/homebrew, PATH launchd minimal possible — ou PDF sans texte extractible) l'outil renvoie « Conversion locale impossible » : le chemin `output/<name>.pdf` n'est jamais communiqué, `inputs/<uuid>.pdf` reste orphelin (pas de `.json`). Scénario : lettre rendue correctement mais l'agent la croit absente et la régénère (`-2`, `-3`…). Correctif : dans `attachDocument` pdf, attraper l'échec de `upload`, renvoyer `{path, tailored:false, uploadError}` ; nettoyer l'orphelin dans `upload` ; chercher `pdftotext` dans `/opt/homebrew/bin:/usr/local/bin`.

6. **important / probable** — `sends.js:92-95` + `truth.js` `recipientInCareerSources`. `email_send` exige que l'adresse figure dans `cv.md, jds, data, inputs, config, modes, relay/offers`. Une adresse lue dans le navigateur (page de contact) ou dans `reports/`/`output/` est refusée (« absente de l'offre, du CV… »), sans voie de repli. En mode propriétaire (aucune restriction ajoutée, seul le clic final) c'est une restriction non prévue qui bloque le parcours e-mail de `modes/email.md`. Correctif : en `ownerMode`, accepter l'adresse et laisser la carte d'approbation finale la montrer ; ou ajouter `reports/` et un enregistrement `relay/seen-addresses` alimenté par les snapshots navigateur.

7. **important / certain (code)** — `attachments.js` `cvAttachment`. `tailored` regroupe tous les PDF produits par la chaîne (`produced` + `document.tailored`), lettres comprises, sans tester le `kind`. Si l'agent joint par erreur (ou seulement) la lettre `cover-….pdf` dans le champ CV, le Bilan dit « CV joint : adapté (PDF de la chaîne du Skill) ». Bilan faux. Correctif : ne compter « adapté » que si `documentKind(file) === 'cv'` (ou rapport/pdf-index `kind=cv`) ; ajouter une ligne « Lettre jointe ».

8. **mineur / certain** — `truth.js` `gatewayToolOutcome`. Tout `exitCode ≠ 0` d'un `career_script` devient `failed` avec la cause fixe « échec signalé par l'outil », y compris les verdicts normaux (`check-liveness` offre expirée, `precheck-duplicate` doublon, `verify-cv-facts`). Bilan : « career_script : 5 réussis, 1 échoué (échec signalé par l'outil) » — faux sens pour un verdict. Correctif : cause `code N` + nom du script ; classer « verdict » les scripts connus pour sortir 1 par construction.

9. **mineur / certain (testé)** — `truth.js` `progressArgument` (l.41-45) : `command.includes('scan')` → `rescan-x`, `scripts/scan-foo.mjs`, tout script du mode propriétaire contenant « scan » devient l'argument `scan`, interprété comme le scan des portails (compteur d'échecs réseau, preuve d'étape). De même `proved()` fait `argument.includes(step.argument)`. Correctif : égalité stricte, `command === 'scan'`.

10. **mineur / probable** — `produced-documents.js:57-82` et `tools.js` `outputFile`. `outputFile` autorise des sous-dossiers (`output/sub/cv.pdf`), mais `listProducedDocuments` ne lit qu'un niveau : un PDF produit en sous-dossier n'est ni listé, ni `tailored`, ni dans `cvTailored` ; `documentsAnswer` ne l'enregistre pas (`exists` faux). Aussi `documentKind('CVAcme.pdf')` → `other` (le motif `cv` exige des séparateurs) : un CV adapté nommé ainsi n'est jamais `cvTailored`. Correctif : parcours récursif borné ; `kind` pris de `pdf-index.tsv` (colonne kind) quand elle existe.

11. **mineur / certain (testé)** — `sends.js:62` `linkedInDraft` : `^(www\.)?linkedin\.com$` refuse `fr.linkedin.com/in/…`, `ch.`, etc. (profils réels fréquents) ; `tools.js` `linkedIn()` écrit toujours `relay/linkedin.json` : un second brouillon écrase le premier alors que le Bilan dit « rédigé ». Correctif : `/^([a-z]{2,3}\.)?(www\.)?linkedin\.com$/`, fichier `relay/linkedin/<uuid>.json`.

12. **mineur / probable** — `tools.js` `entries()` : `names.slice(0, 500)` AVANT tout tri → au-delà de 500 fiches, des fiches récentes sont absentes de `career_offers` ; une seule fiche JSON corrompue (`schema.parse` ou `JSON.parse`) fait échouer toute la liste (idem `drafts()`). 13. **mineur / probable** — `sends.js` `smtpConfig` appelé en paramètre par défaut du constructeur d'`EmailGateway` (instancié à chaque `registerCareerTools`) : `CAREER_SMTP_HOST` défini sans `CAREER_SMTP_FROM` valide → `ZodError` → tout le serveur d'outils career échoue au démarrage, pas seulement `email_send`. ## Ce qui bloque une candidature career-ops de bout en bout

- Offre → évaluation : rien de bloquant propre au code ; risque #2 (lectures de fichiers « if exists » comptées en échec) et #3 (scan / PDF qui expirent à 60 s, sortie perdue).
- Rapport → suivi : le format TSV (en-tête + une ligne, alias) est cohérent avec `AGENTS.md` du Skill et `merge-tracker.mjs` ; seul #15 (fusion à zéro non signalée) fausse le Bilan.
- CV / lettre : chaîne `build-cv-html → verify-cv-facts → generate-pdf` correctement bornée ; blocages possibles #10 (sous-dossier / nom `CVAcme` non vus comme CV adapté) et #5 (`career_document` pdf échoue après avoir rendu le fichier).
- Formulaire → envoi : #7 (Bilan faux sur la pièce jointe) ; e-mail : #6 (destinataire refusé s'il n'est pas dans les fichiers sources) ; LinkedIn : #11.
- Boîte d'entrée (pipeline) : #1 bloque définitivement les écritures de `data/pipeline.md` dès qu'une ligne sort du format strict.
- Bilan trop indulgent : #4 (prompts anglais, négations, pluriels).

## Ce qui semble solide

- Confinement de chemins : `pathSchema` + `userPath`/`systemPath` fermés, `readConfined`/`writeConfined` (O_NOFOLLOW, refus des liens, écriture atomique), `outsidePath` qui résout l'ancêtre existant le plus profond (liens sous `data/`, `output/`), `globMatch` linéaire (pas de ReDoS), refus des dossiers/motifs avec liste des fichiers lisibles.
- Arguments des scripts : grammaire fermée hors mode propriétaire, un argv par valeur, pas de shell, `--permission` + préchargement sans réseau pour les contrôles isolés, entrée standard fermée.
- Reçu de revue (`sourceSnapshot` / `assertSourceReview`) : versionné, ne se réécrit jamais, messages de différences clairs ; `review-migration` ne fait que mesurer / migrer à octets identiques.
- Journal d'envoi e-mail : réservation `wx` avant SMTP, jamais de relance automatique, approbation un par un, résultat incertain assumé.
- `checkTrackerAddition` aligné sur le Skill (en-tête, alias, étiquettes obligatoires, score `X.X/5` ou sentinelle), création initiale de `data/applications.md` réservée à l'en-tête seul.
- Comptage Bilan par appel (clés `acp:`/`gateway:`) qui absorbe les mises à jour ACP répétées ; regex d'extraction (`trackerSummary`, `scanUnreachable`, `factsUnsourced`) ancrées et testées contre les sorties réelles du Skill.
