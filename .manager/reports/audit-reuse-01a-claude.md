## Vérifications faites sans trouver de défaut (preuves)

- **Résolution vers le bon élément** : `aria-ref` n'accepte que `_lastAriaSnapshotForQuery.info.get(ref)` et exige `element.isConnected` (bundle `_createAriaRefEngine`) ; les refs sont uniques par document (`lastRef` monotone) et réattribuées au même nœud seulement si rôle+nom inchangés (`computeAriaRef`). Une ref ne peut donc pas passer d'un nœud à un autre dans un même document, sauf le cas iframe du n° 9.
- **Refs de la frame principale entre documents** : la frame principale est renumérotée à chaque nouveau document réel (`coreBundle.js:24546-24548`) ; une ancienne `eN`/`fKeN` ne résout rien dans le nouveau document, même si `snapshotRefs` la contenait encore.
- **Accord humain intact avec ref** : `describe` lit l'élément vivant (pas la description du snapshot) via la même ref (`index.js:71-73`), la sensibilité, `inForm` et l'aperçu d'envoi en découlent ; `submissionPreview` et la double lecture avant/après passent par le même `target` ; un nœud remplacé donne « introuvable » (plus strict que le sélecteur, qui acceptait un nœud équivalent). `BrowserGateway.call` sérialise les appels (`index.js:48-54`) : aucun `browser.snapshot` ne s'intercale entre `describe`, approbation et `perform`.
- **Pas de fuite dans l'accord** : pour `browser.type`, `args` = `{ ref|selector, textLength }` (`index.js:109-114`) ; `describe` met `value: null` ; l'aperçu masque `password|hidden`. Aucun texte tapé n'atteint `approve`.
- **Écouteur `framenavigated`** : posé une seule fois par page (`WeakSet`), jamais sur une page non suivie parce que la première action avec ref suit forcément un `browser.snapshot` passé par `perform` ; `reset()` et `goto` vident l'état ; `ensure()` (l.269-274) et `dropConnection` (l.1121-1141) ne le vident pas mais la page rouverte est `about:blank` (URL ≠ `snapshotUrl`) et les objets Playwright d'une reconnexion n'ont plus d'instantané : refus sûr. Pas de fuite d'écouteur.
- **Course snapshot/navigation** (navigation entre `ariaSnapshot` et l'affectation, l.818-822) : l'ensemble est alors bâti avec l'ancienne page mais `snapshotUrl` de la nouvelle ; sans effet grâce à la renumérotation Playwright (erreur « introuvable », pas d'action).

## Ce qui est logique et peut rester

- **`selector` conservé pour click/type/upload/download** : 96 usages dans les tests, `browser.download` n'a pas de ref, et l'extraction multiple (`h3` + `limit=3`) en a besoin ; cohérent avec `reuse-plan.md` (« conserver les sélecteurs historiques ») et l'instruction de l'orchestrateur modifiée (`orchestrator/index.js:621`).
- **`observed()` via `target.evaluate`** (l.912) : nécessaire pour lire le témoin dans la fenêtre de l'iframe ; le test Chrome « dom-hidden-tab » sur la ref d'iframe (`owner-browser.test.js:88-90`) le prouve (avec `page.evaluate`, il échouerait en « Clic non délivré »). Seul le délai pose problème (n° 1).
- **Contrôle `snapshotUrl` + ensemble `snapshotRefs`** malgré la renumérotation Playwright : défense en profondeur, et il restreint les refs à celles rendues dans le texte (Playwright résout aussi les refs de nœuds élagués du rendu, `ariaSnapshotDistiller.ts:31`).
- **Test unitaire « panne de résolution conserve sa cause »** (`browser-ref-review.test.js:4-18`) : bien conçu, devient rouge si on traduit toute erreur en « introuvable ».
- **Test Chrome de références** : les assertions « compteur inchangé » (`data-hits` nul) détectent bien un clic sur l'autre élément ; iframe rechargée et navigation sont réellement exercées.
- **`browser.extract` : défaut `body` déplacé dans `perform`** (`selector` optionnel au schéma) : même comportement pour les appelants existants.
- **Serveur de statistiques fictif lié à `127.0.0.1`** (`owner-browser.test.js`, multiStepSite) : l'assertion `statsGet > 0` (« joignable ») empêche un test vide si `localhost` résolvait en `::1`.
- **Messages d'accord** (`rawInput.args` avec `ref` seul) : l'utilisateur voit le texte de l'élément (`title`) ; suffisant pour les éléments hors iframe (voir n° 14 pour les iframes).
