## Décisions provisoires

- La demande actuelle du propriétaire autorise des tests réels locaux, contrairement à la restriction historique du brief `fix-open-01`. Les actions externes irréversibles restent soumises à l'autorisation explicite du message actuel. Le seul prompt réel réussi à ce stade est Codex ; Claude a échoué sur l'authentification.
- Aucun fichier d'authentification ne sera lu. Les capacités seront vérifiées par la session ACP et par des prompts courts, lorsque possible.
- Le refus LinkedIn codé en dur était une interdiction générale contraire à la demande actuelle. En mode standard, la politique d'origine reste en place ; en mode propriétaire, l'accord explicite sur l'envoi demeure exigé par la demande actuelle. Alternative rejetée : activer `AGENT_PLATFORM_AUTO_SEND`, car une variable cachée rendrait l'envoi silencieux.
- Le modèle Gemini auparavant choisi par nom constant (`gemini-3.1-flash-lite`) n'était pas fondé sur la session. Le défaut de la session sera laissé au CLI ; seul un identifiant annoncé peut être sélectionné explicitement.
- `career-ops` désactivait les outils natifs de Gemini et annulait systématiquement les permissions ACP ; ces deux restrictions de plateforme ont été retirées. Les modes `bypassPermissions`/`yolo` ne sont plus choisis automatiquement en mode propriétaire ; les permissions ACP demandent désormais une décision dans l'interface. Les actions navigateur ordinaires restent automatiques, les soumissions visibles.

## Inventaire des contradictions et décisions

- `packages/orchestrator/index.js` : défaut `fixture` sous choix Auto, échec « Mode réel désactivé » hors drapeau live, substitution forcée par Gemini pour career-ops et permissions ACP annulées. Le défaut est Auto ; l'agent choisi reste celui demandé, ses modèles/modes sont comparés aux annonces ACP ; une absence d'authentification reste un échec visible. Le mode réel demeure explicitement nécessaire hors mode propriétaire. Le plan refuse un agent réel avec navigateur fictif.
- `packages/browser-gateway/index.js` et `packages/browser-gateway/cdp.js` : refus de toute écriture LinkedIn, même avec décision de l'utilisateur. Refus spécifique retiré ; les décisions de soumission, la garde des POST sensibles et la vérification des octets envoyés restent actives. `packages/policy-engine/run-policy.js` conserve le contrôle HTTPS/DNS/réseau privé et applique les domaines configurés par mission ; la politique de l'OS et du fournisseur n'est pas contournée.
- `packages/career-ops/integration.js`, `packages/orchestrator/skill-router.js` : consignes qui interdisaient la recherche native, forçaient une méthode métier codée par la plateforme, un modèle Gemini et annulaient les permissions. Le Skill détermine sa méthode ; le routeur constate l'intention et les étapes sans imposer un outil de recherche. Les sources non fiables n'autorisent aucune action. Les permissions sensibles passent par l'interface.
- `packages/career-ops/tools.js` : liste fermée des scripts et extension concurrente non approuvée. Scripts `scripts/*` revus par hash, bornés au dossier, avec décision explicite par invocation ; un refus, une annulation ou un code modifié bloquent l'exécution. `packages/career-ops/sends.js` garde la preuve du destinataire, l'accord SMTP et l'ID d'envoi anti-rejeu ; les raccourcis concurrents ont été retirés.
- `packages/orchestrator/packs.js` : Auto pouvait choisir career-ops malgré un Skill Najah explicitement choisi ; le Skill sélectionné prime maintenant sur les mots-clés du manifeste. `domain-packs/najah/manifest.yaml` déclare si un workflow utilise des fixtures ou des sources réelles. Le résultat Najah de démonstration reste `simulated:true`, même avec agent réel ; l'interface distingue modèle appelé et provenance des données.
- `apps/api/server.js` et le front : `publicAgents` omettait l'état d'inférence, donc « détecté » pouvait sembler « opérationnel » ; plan et run exposent désormais agent, modèle demandé/sélectionné, mode ACP, navigateur, source fictive/réelle, permissions, événements et portée de vérification.
