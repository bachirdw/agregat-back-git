## Points examinés sans défaut
- **Extraction** : `#setChecked`, `#selectValues` et `#fillText` sont des déplacements textuels identiques de `check`/`select`/`type` (diff relu ligne à ligne). Les retours sont inchangés, l'`url` est ajoutée par l'appelant, `assertLanded` est conservé après check/select et absent après type comme avant. Aucune régression observée en lecture.
- **Contrat provider `{ref, kind, value}`** : le gateway produit `text`→chaîne, `checkbox`→booléen, `radio`→`true`, `select`→tableau. Le schéma impose la clé juste par `kind`, donc jamais `undefined` côté provider. `text:''` (effacement) est conservé (`'' !== undefined`).
- **Gateway** : `describe` de chaque champ avant accord ; champ introuvable → `Élément introuvable : <ref>` avant tout accord ; `sensitive` agrégé ; un seul accord ; `args` d'accord sans `text` (remplacé par `textLength`) ; comparaison tableau à tableau après accord (`isDeepStrictEqual` sur tableaux) ; `sending` jamais vrai pour `fillForm` ; garde LinkedIn appliquée (`effect: write`). Aucune fuite de `sendApproved`/`formStep`. Les 5 tests passent.
- **Schéma zod** : `.strict()` aux deux niveaux ; clé interdite/requise selon `kind` (messages « X requis/interdit pour kind K ») ; ref dupliquée refusée avec message ; limites 1..30 champs, 1..20 options ; `kind` absent ou inconnu donne un message français ; `superRefine` non exécuté si un type est invalide (pas de messages en cascade trompeurs). Conversion SDK MCP (draft-07) sans erreur : `fields` = tableau d'objets, `required:[ref,kind]`, `additionalProperties:false`.
- **Arrêt au premier échec, ordre, ref périmée** : boucle séquentielle, pas de retry (une case ne bascule pas deux fois), `filled` n'inclut que les champs réussis ; la ref périmée lève `Référence eN introuvable… reprends un snapshot`, enveloppée par `Champ N (ref)`.
- **Onglet caché** : `hidden` en tête de réponse ; chaque `#setChecked` recalcule `hidden` ; `fill`/`selectOption`/`domClick` inchangés.
- **Instructions et manifeste** : `browser_fillForm` cité dans le prompt orchestrateur, `CAREER_INSTRUCTIONS`, README et manifeste career-ops. L'outil MCP porte le nom `browser_fillForm` (`cap.id.replace('.', '_')`). `FixturePageProvider` répond `done: id` sans traitement spécifique. Aucun autre fichier n'énumère les capacités browser (grep).
