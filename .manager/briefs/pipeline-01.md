## But
Un prompt « traite la boîte d'entrée », « pipeline », « travaille les offres en attente » déclenche un intent `pipeline` du manifeste qui suit `modes/pipeline.md` : lecture de `data/pipeline.md`, pour chaque entrée `- [ ]` : `precheck-duplicate` → `check-liveness` → évaluation (réutiliser les étapes de `evaluate` : lecture, `reserve-report-num`, rapport, TSV, `merge-tracker`) → entrée marquée `- [x]` (ou `- [!]` si illisible/non confirmée, jamais « fermée » sans preuve) par `career_write data/pipeline.md` selon le format exact du Skill. Les offres trouvées par Relay hors scan (navigateur, `jobs_search_live`) entrent dans la boîte par l'étape `pipeline` de `search` déjà créée par `skill-suivi-01`, avec `url-key` pour éviter les doublons (règle du Skill : un doublon visible vaut mieux qu'une fusion silencieuse ; ne pas inventer de dédoublonnage plus agressif).
