## Points examinés sans défaut

- **Rejet / non-résolution** : `stopProcess` n'a aucune opération qui peut lever hors `try/catch` (`processGroupState` capture tout, `signal()` capture, `child.kill` capturé) ; toutes les boucles sont bornées par `Date.now() < until` ; pire cas 1 s (inconnu initial) + 1,5 s + 1 s = 3,5 s. Aucun rejet non géré possible.
- **Idempotence / courses** : `this.closing` renvoie la même promesse (testé) ; `stopped` est posé avant tout await ; close() pendant `start()` — `spawn` est synchrone au premier tick de `startProcess`, donc `child.pid` est connu (ou `undefined` sur ENOENT → `none`) ; double close, close par l'abort de `request()` puis par `finally` de l'orchestrateur : sans effet supplémentaire. Setsid de libuv fini avant le retour de `spawn` : pas de signal envoyé à un groupe pas encore créé.
- **Chef sorti avant close, petits-enfants vivants** : le groupe est sondé et signalé (test existant du petit-enfant, vert) ; chef zombie non récolté sur macOS : EPERM → `unknown` → réattente 1 s → `dead` (preuve zombie-probe.log) ; avec petit-enfant vivant le groupe répond `alive`.
- **SIGKILL sur `unknown`** : impossible dans le code (`if (state !== 'alive') return state` aux deux endroits) ; test EPERM après SIGTERM et EPERM dès le départ le vérifient (aucun signal non nul).
- **Windows (simulé via `process.platform`)** : branche `child.kill` + événement `exit`, garde `exitCode/signalCode` avant d'écouter, `?? 'unknown'` si l'attente expire, listeners `once` ; fonctionnel sur un enfant réel et sur un enfant déjà sorti (`dead`). Petits-enfants non tués sous Windows : comportement antérieur inchangé.
- **Espion `process.kill`** : restauré dans `finally`, séquentiel dans le fichier (pas de course inter-tests), `platform` redéfini puis restauré ; nettoyage `t.after` tue le groupe (`-child.pid`), y compris le petit-enfant dans le test EPERM (même pgid). Aucun processus node résiduel constaté après exécution.
- **Callers** : tous appellent `close()` sans lire le retour et sans `.catch` ; sans rejet possible, aucune régression ; l'ordre `cancel()` puis `close()` est conservé.
- **Source acpx** : `isProcessDefinitelyDead` identique ; en-tête MIT et notice complète dans THIRD_PARTY_NOTICES.md.

Aucun défaut de gravité haute. Constat principal : n° 1 (réutilisation de pgid de même utilisateur).
